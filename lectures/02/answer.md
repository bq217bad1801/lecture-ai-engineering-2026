最終lossは、40ステップ時点で記録された最後の10ステップ（31〜40）の平均学習lossである。
全学習区間の平均を表す `train_loss` とは区別した。
学習時間は `trainer.state.log_history` の `train_runtime` を使い、モデルの取得時間と評価時間は含めていない。

学習率を半分にした条件では、形式はどちらも21/21で、内容の正解が19問から20問に増えた。
変更後の最終lossは基準より高く、学習lossの大小と評価時の正解数は一致しなかった。
内容の判定が不正解から正解に変わったのは「成績はいつ出ますか」「オフィスアワーは事前予約が必要ですか」だった。
内容の判定が正解から不正解に変わったのは「PDF 以外でも出せますか」だった。
lossは学習用の14件に対する値なので、その大小だけで未見の質問への正しさを判断できない。
各条件を1回ずつ、21問で測った結果であり、学習率の一般的な優劣までは結論しない。

#### 学習後に残った失敗

| 条件 | 質問 | 学習後の回答 | 失敗の型 |
|---|---|---|---|
| 基準 | 成績はいつ出ますか | 提出期限は 9 月 30 日 23:59（日本時間）です。 | 根拠なしの質問に断定 |
| 基準 | オフィスアワーは事前予約が必要ですか | 質問は毎週火曜 17:00〜18:00 のオフィスアワーで受け付けます。 | 根拠なしの質問に断定 |
| 変更後 | PDF 以外でも出せますか | この FAQ には記載がありません。運営に確認が必要です。 | 根拠ありの質問に確認要求 |

形式の判定はJSONのキーと型を確認し、内容の判定は `needs_review` と必須語句を確認する。
たとえば基準設定では、成績の公開時期を聞かれたのに課題の提出期限を答えていた。
JSONとして読める回答でも、質問に対応する根拠がFAQにあるかを別に確かめる必要がある。
語句の一致による採点には限界があるため、残った誤答は回答原文でも確認した。

退行した質問は、基準設定で `[]`、変更後で `[]` だった。
今回は学習前に形式と内容を両方満たした質問が0件なので、退行なしという結果から既存能力の保持は評価できない。

#### 知識を問う質問

`format_error` は形式違反、`needs_review` は確認要求、`asserted` は断定を表す。

| 質問 | 学習前 | 基準の学習後 | 変更後の学習後 |
|---|---|---|---|
| この講座の最終課題の締切はいつですか | format_error | asserted | asserted |
| 担当教員の名前は何ですか | format_error | needs_review | needs_review |
| 次回の講義のテーマは何ですか | format_error | needs_review | needs_review |
| 課題の提出期限はいつですか | format_error | asserted | asserted |

最終課題の締切はFAQにないが、基準設定では通常の課題の提出期限を流用して断定した。
担当教員名と次回のテーマには確認を求めており、未知の質問に対する判断は質問によって異なった。
対照の「課題の提出期限」はFAQにあるので、正しい日付で断定するのが期待する動作である。

配布コードの「FAQ にある」列は `q in gold` で判定している。
対照質問は学習用にあり、test用の `gold` にはないため、この列がfalseになる。
結果JSONには元の表示を残し、この考察では実際のFAQの内容で判定した。

### ファインチューニングが向く場面と向かない場面についての考察

今回のデータでは、JSONのキーや型、回答文の書き方を揃える用途に効果があった。
繰り返し使う出力形式や、一定の基準で分類する処理を学習させたい場面で使いやすいと考える。

締切など更新される事実の管理や、根拠のない質問への断定を確実に防ぐ用途には、この学習だけでは不足する。
根拠を更新しやすい検索の仕組みや、根拠が取れない場合の確認要求、出力形式の検証を組み合わせたい。
検索との性能比較は今回の実験には含めていない。

### 再現手順と結果ファイル

1. [配布ノートブック](../../notebooks/lora_format_tuning.ipynb)をColabにコピーし、T4を選ぶ。
2. `lr=2e-4` でセクション0〜7を実行し、結果を保存する。
3. `lr` だけを `1e-4` に変更し、セッションを再起動して同じ範囲を実行する。
4. 下記の保存処理で学習ログと各質問の回答を結果JSONへ追加し、条件ごとに名前を変えて保存する。

```python
history = trainer.state.log_history
last = [r for r in history if "loss" in r][-1]
run = next(r for r in reversed(history) if "train_runtime" in r)
result["training"] = {
    "seconds": run["train_runtime"], "final_loss": last["loss"],
    "final_loss_definition": "last logged training loss (steps 31-40)",
    "train_loss": run["train_loss"], "global_step": trainer.state.global_step,
    "epoch": trainer.state.epoch, "log_history": history,
}
result["evaluation"] = {"before": before_rows, "after": after_rows}
name = "result_baseline.json" if CONFIG["lr"] == 2e-4 else "result_lr_1e-4.json"
(WORK / name).write_text(json.dumps(result, ensure_ascii=False, indent=2), encoding="utf-8")
```

基準の結果は [result_baseline.json](result_baseline.json)、変更後は [result_lr_1e-4.json](result_lr_1e-4.json) に保存した。
両ファイルには設定、ライブラリの版、回答原文、採点結果、知識質問、学習ログを含めた。
