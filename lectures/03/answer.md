# 第3回 解答

## 演習

### 第1回（素のLLM）とエージェントの回答の違い

第1回と同じ「AIE2026の講座の宿題にある『3レベル』とは何ですか？」という質問を実行した。
第1回に記録した素のLLMの回答は、講座の意味を推測し、「基礎・応用・発展」という一般的な難易度の説明をしていた。
今回のエージェントは `search_glossary` で「3レベル」を検索し、次のように回答した。

- 基礎：講義内容の確認
- 実装：自分でコードを書く
- 発展：調査や試行
- どれか一つに取り組めば、その回の宿題完了となる。
- 関連する回：第1回

`data/glossary.json` の `homework-levels` にある定義と一致していた。
モデルの知識だけで推測するのではなく、講座の用語集を参照して回答した点が異なる。
なお、第1回の回答は過去に記録したものを比較に使い、今回再実行したものではない。

### traceで見えたツール呼び出し

| 質問 | 実際のツール呼び出し | requests | tool_calls |
| --- | --- | ---: | ---: |
| AIE2026の講座の宿題にある「3レベル」とは何ですか？ | `search_glossary({'query': '3レベル'})` | 2 | 1 |
| LoRA とQLoRAの違いは？ | `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` | 2 | 2 |
| 第2回の内容から確認問題を1問出して | `make_quiz({'lecture': 2})` | 2 | 1 |

LoRAとQLoRAの比較では、用語を一つずつ検索していた。
回答は、LoRAでは元の重みを固定して小さな低ランク行列を学習し、QLoRAではベースモデルを4ビットなどに量子化してメモリ使用量を減らすと説明し、関連する回として第2回を示した。

### 1つの質問でのLLMの呼び出し回数

今回の3件はいずれも `requests=2` だった。
最初のモデル呼び出しでツールの使用を依頼し、プログラムが返した結果を受け取った後、次のモデル呼び出しで回答を生成する流れを確認した。
LoRAとQLoRAはツールを2回呼んだが、LLMの呼び出しは2回であり、ツールの実行回数とLLMの呼び出し回数は同じではなかった。
これらは今回の実測値であり、毎回同じ回数になるとは限らない。

### 追加したツールとdocstring

`app/tools.py` に `make_quiz(lecture: int) -> str` を追加し、`app/agent.py` で `agent.tool_plain(tools.make_quiz)` として登録した。
docstringには次の説明を書いた。

```text
指定した回の用語から1つを選び、確認問題と答えを返す。

「第2回の確認問題を1問出して」のように、復習用の問題を求められたときに使う。
lecture には講義の回を1始まりの整数で指定する。答えは用語集の定義を使う。
```

処理は、用語集から `lecture` が一致する用語を集め、`random.choice` で一つ選び、問題と定義をJSON文字列で返す構成にした。
新しい答えを生成せず、用語集の定義をそのまま答えに使うことで、問題と根拠を対応させた。
用語がない回は抽選前に判定し、出題できない旨を返す。
空の候補から `random.choice` すると例外になるため、この分岐が必要である。

`--list-tools` で、元の2ツールに `make_quiz` が加わり、合計3個になったことを確認した。
登録後に「第2回の内容から確認問題を1問出して」と依頼すると、次の呼び出しが記録された。

```text
[tool call] make_quiz({'lecture': 2})
question: 「ランク（LoRAのr）」の意味は？
answer: LoRAで使う低ランク行列の大きさを決めるハイパーパラメータ。
        大きいほど表現力が上がるが、学習するパラメータとメモリも増える。
requests=2, tool_calls=1
```

上記はtraceのツール結果を読みやすく抜粋したものである。
利用者向けの最終回答では問題のみを提示し、答えを知りたい場合に申し出るよう案内していた。
ツールの返り値に答えが含まれることと、モデルがその答えをすぐに表示することは別だった。
ツール登録後は既存の `INSTRUCTIONS` のままで呼ばれたため、追加の指示は残していない。

## 宿題

### 取り組んだレベル

発展（a）：同じ指示とツールを使い、Google ADKでエージェントを作り直した。

### やったこと

`adk_agent/glossary_agent/agent.py` と `__init__.py` を作成した。
演習の `INSTRUCTIONS` と、`search_glossary`、`get_lecture_summary`、`make_quiz` を読み込み、そのまま使った。
宿題のために `app/` のコードは変更していない。

Pydantic AI版では `Agent(instructions=INSTRUCTIONS)` を作成した後、`agent.tool_plain(...)` でツールを一つずつ登録していた。
ADK版では `root_agent = Agent(...)` に `instruction=INSTRUCTIONS` と `tools=[...]` を渡してまとめて登録した。
`__init__.py` の `from . import agent` は、パッケージを読み込む際にエージェントの定義も読み込むために置いた。

次のコマンドで起動し、演習と同じ質問を入力した。

```bash
PYTHONPATH=. uv run --with google-adk adk run --in_memory adk_agent/glossary_agent
```

`PYTHONPATH=.` はリポジトリ直下の `app` を読み込むために付けた。
`--with google-adk` でADKを一時的に追加し、`pyproject.toml` と `uv.lock` は変更していない。
比較用には各質問を新しい会話で実行し、`--jsonl` の出力でツール名と引数も確認した。

### 結果

| 質問 | Pydantic AI版（演習） | ADK版 |
| --- | --- | --- |
| AIE2026の講座の宿題にある「3レベル」とは何ですか？ | 「基礎・実装・発展」と、どれか一つで完了することを回答した。 | 同じ3段階と完了条件を回答した。「第1回」の表記は末尾で重複していた。 |
| LoRA とQLoRAの違いは？ | LoRAの低ランク行列による学習と、QLoRAの量子化によるメモリ削減を説明した。 | 同じ要点に加え、学習するパラメータが少なく、アダプタを小さなファイルで保存できることも説明した。 |
| 第2回の内容から確認問題を1問出して | 「ランク（LoRAのr）」の意味を問う問題を出した。 | 「教師ありファインチューニング（SFT）」の意味を問う問題を出した。 |

ADK版でも、3レベルの質問では `search_glossary({'query': '3レベル'})` が呼ばれた。
LoRAとQLoRAは `search_glossary` をそれぞれの用語で1回ずつ呼び、確認問題では `make_quiz({'lecture': 2})` が呼ばれた。
いずれも演習版で観察した呼び出しと同じだった。
確認問題の最終回答は、両方とも問題を先に提示し、答え合わせをしたい場合に申し出るよう案内していた。

### 気づき・疑問

同じPython関数と指示文を再利用できたため、エージェントを組み立てる部分の変更だけでADK版を動かせた。
指示や道具の内容をそろえても、説明の詳しさや言い回しは完全には一致しなかった。
確認問題の用語の違いは `random.choice` による抽選の影響を含むため、フレームワークの性能差とは判断できない。
今回の比較だけで優劣を決めず、同じ質問を繰り返した場合に、ツールの選び方や回答がどの程度変わるかも確認したい。
